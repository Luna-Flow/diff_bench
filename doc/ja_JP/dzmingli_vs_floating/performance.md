# 性能分析

拡張 common-digits は 19 操作について 1,368/1,368 検証に合格しました。scaling は
1,476 件を検証し、新規 14 の scalable exact operation を 1,024 桁まで測定します。

scaling の交差点は 64 桁と 256 桁の間です。1,024 桁の arithmetic-only 中央値は
元の 5 操作について floating GDA が `0.383–17.586 µs/op`、DzmingLi が
`12.351–80.126 µs/op`、full-path はそれぞれ `26.835–61.180 µs/op` と
`156.160–209.601 µs/op` です。

DzmingLi の算術は 4,096 桁以降で不正なため speedup として扱いません。20,000 桁の GDA
arithmetic-only は加算 `17.037`、減算 `19.084`、除算 `74.468`、比較 `0.380 µs/op`、
full-path は順に `854.378`、`916.372`、`528.483`、`881.238 µs/op` です。

DzmingLi の arithmetic-only 比較曲線は大規模入力で大きく上下します。4,096、8,192、
10,000、16,384、20,000 桁の中央値は順に `110.370`、`0.103`、`723.515`、
`0.100`、`2,377.639 µs/op` です。これは通常の測定ノイズではなく、比較処理に
データ依存の短絡経路があるためです。一部の fixture は符号、指数、有効桁数などの
メタデータだけで大小を即座に判定できますが、別の fixture では長い係数を深く比較する
必要があります。この 2 種類の実行経路を折れ線で結ぶことで尖りが生じるため、桁数だけに
起因するアルゴリズムの不安定性とは解釈できません。full-path には桁数とともに増加する
解析・構築コストも含まれるため、同じ跳動は目立ちません。比較性能は early mismatch、
late mismatch、equal values などの入力クラスに分けて評価する必要があります。
