# 性能分析

現在の `0.7.1` run は scaling で 1,476 件を検証し、1,368 件が合格、DzmingLi の 108 件が失敗しました。拡張 common-digits は 19 操作について 1,368/1,368 検証に合格しています。

双方が oracle に合格する 1,024 桁では、arithmetic-only の floating GDA は `0.978–16.798 µs/op`、DzmingLi は `12.459–78.978 µs/op` です。full-path はそれぞれ `7.427–24.133 µs/op` と `152.145–205.549 µs/op` で、GDA の speedup は操作と scope により `3.54–95.44×` です。

DzmingLi の算術は 4,096 桁以降で不正なため、その点は speedup として扱いません。20,000 桁の検証済み GDA は arithmetic-only で加算 `14.810`、減算 `15.083`、除算 `60.588`、比較 `0.130 µs/op`、full-path は順に `154.468`、`155.582`、`131.363`、`139.865 µs/op` です。

DzmingLi の arithmetic-only 比較は大規模入力でデータ依存の短絡経路を示します。4,096、8,192、10,000、16,384、20,000 桁の中央値は `105.918`、`0.103`、`675.705`、`0.101`、`2,203.063 µs/op` です。符号、指数、有効桁数だけで判定できる fixture と長い係数を深く比較する fixture が混在するためで、単一の桁数スケーリングとして解釈できません。
