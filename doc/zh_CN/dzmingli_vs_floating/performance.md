# 性能分析

扩展 common-digits 对 19 个操作执行 1,368 次校验并全部通过；scaling 共执行
1,476 次校验，新增 14 个可扩展精确操作并运行到 1,024 位。

scaling 的转折点位于 64 与 256 位之间。1,024 位时，floating GDA 的
原五项 arithmetic-only 中位数为 `0.383–17.586 µs/op`，DzmingLi 为
`12.351–80.126 µs/op`；full-path 分别为 `26.835–61.180 µs/op` 与
`156.160–209.601 µs/op`。

DzmingLi 从 4,096 位开始算术不正确，因此这些点不能解释为 speedup。20,000 位时，
GDA 的 arithmetic-only 加、减、除、比较分别为 `17.037`、`19.084`、`74.468`、
`0.380 µs/op`；full-path 分别为 `854.378`、`916.372`、`528.483`、`881.238 µs/op`。

DzmingLi 的 arithmetic-only 比较曲线在大规模输入处出现明显跳动：4,096、8,192、
10,000、16,384 和 20,000 位的中位数依次为 `110.370`、`0.103`、`723.515`、
`0.100` 和 `2,377.639 µs/op`。这不是普通的测量噪声，而是比较操作的数据相关短路：
部分 fixture 可由符号、指数或有效位数等元数据立即判定大小，另一些则需要深入比较长系数。
折线连接了这两类不同执行路径，因此不能将其尖峰解释为算法仅随位数变化时的不稳定性。
full-path 还包含随位数增长的解析和构造成本，因而不会呈现同样明显的跳动。比较性能应按
early mismatch、late mismatch 和 equal values 等输入类别分别评估。
